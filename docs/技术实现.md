# 原生肩键资格扩展

## 结构

- `ui`：原生设置界面、配置同步、应用选择和草稿恢复。
- `data`：不可变配置、版本比较保存、配置 Provider 与内存状态。
- `root`：一次性只读空间信息与应用目录读取。
- `hook`：游戏魔盒 daemon 准入扩展与 assistantui 菜单分类适配。
- `core`：应用身份、准入、作用域、桥接和恢复规则。

配置中的应用身份为 Android userId、用户序列号和包名。重建空间不能继承旧序列号资格，未选实例不获得模块追加资格。

## 原生准入与分类

daemon 只在原厂 `g.t0(int,String)` 的真实同步调用内解析前台身份，在其内部 `i0.A()` 的列表副本中追加选中的包名。整数参数不作为 userId；不改变全局名单，不主动调用或重放原厂生命周期。

assistantui 通过 `k.p`、`k.q` 扩展所选实例的肩键菜单资格，保留原生硬件结果或检查。`e0.c1` 的改动限定于 8 个同步作用域：`be.a.m/u/h`、`ce.i0.processPressAnim`、SettingsView 的 `X0/c1`、PreferencesView 的 `x0`、UserGuideView 的 `A0`。6 个原生屏障遮蔽外层资格：`k.q`、`utils.l.a`、`e0.V0`、`mc.b.h`、`nb.h.l`、`shoulder.a.onGameSdkEvent`。

UI 通过 presenter 字段链核对实际包名，SettingsView 的 `R` 还需匹配 presenter 的 `d`。`GAME_REVIEW`、SDK 场景和补帧分类保持原厂行为。专用游戏转通用分类还要求原生 Context 的用户匹配，且左右 `mapping_type` 均为零；不明或读取失败时保持原生。

输入分类作用域仅使用内存快照，包括按键动画间接调用 `k.p` 的路径，不新增逐次前台、Settings 或 Provider 查询。线程局部作用域在返回时恢复，不跨线程继承。

模块不持有肩键输入、监听、驱动或方案所有权。原厂序列化、提交、保存、关闭和复位方法继续执行；改变选择或开关不强制关闭已经开启的原生输出。

## 事件与配置桥

assistantui 的任务、用户、屏幕和原生前后台事件先使资格快照失效，再合并到主线程重新核验。daemon 不注册独立任务观察，每次真实准入入口重查身份。

配置在初始化、配置变化和明确就绪事件读取。Provider Binder 死亡撤销配置缓存，assistantui Binder 死亡撤销 daemon 的追加就绪条件。连接/读取失败使用有限退避；状态发布失败撤销连接并等待后续真实生命周期或配置事件。缓存读取不发 IPC，不启动周期轮询。

Provider 以 Android 系统共享 UID 1000 为信任边界，用 Provider epoch、publisher Binder/PID/generation 约束连接一致性。状态仅在内存中保存，不把自报进程类别当作特定包认证。

## 配置与草稿

可见界面观察配置变化，并在返回前台时异步重载。配置读写使用独立串行队列，读代次门禁防止保存前的旧结果覆盖新配置；页面结束后停止排入新读取。

新增草稿保存完整应用身份和原确认空间范围，不恢复应用目录或界面 Root 就绪状态，也不自动扫描。用户可确认原范围重新读取，或主动检查空间后确认调整范围。不可用项继续保留，由用户明确移除后更新实际已读取范围。四页分别保存滚动位置，未布局或新增目录未恢复时不采集零值覆盖原位置。

Root 帮助程序只执行 `inspect` 或带明确空间身份的 `scan`。枚举应用前核验确认范围，读取前后再次核验空间序列号和解锁状态；结果使用有界唯一 JSON 帧，客户端再次对照请求范围。
